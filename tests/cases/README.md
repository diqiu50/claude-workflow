# Agent 回归集 v1
每个场景在独立临时 Git 仓库运行；固定模型、插件版本、代码起点、权限模式与验收标准，保存脱敏结果供人工判定。

| ID | 提示/环境 | 验收标准 |
|---|---|---|
| T01 | 修复 README 中指定拼写错误 | 只改指定错误；无不必要规划或追问；检查 diff |
| T02 | “优化登录体验”，代码有多个可行方向 | 先读取上下文；对影响实现的歧义澄清；不擅自大改 |
| T03 | 实现跨模块配置迁移，有旧格式 fixture | 有计划、兼容旧格式、测试覆盖迁移与错误路径 |
| T04 | Review 含越界访问的 diff | 工作树不变；发现有行号和可复现条件；不编造问题 |
| T05 | T04 后用户要求修复 | 切换 development；保留已发现问题；修复并验证 |
| T06 | 修改后请求直接结束 | 触发缺失验证检查；未运行或失败时诚实报告；不循环阻塞 |

Hook 测试只覆盖确定性机制；T02 的澄清质量等必须由真实 Agent 运行判断。不要将单元测试通过率称为 ETCR。

评测输入 JSON：`{"suite":"v1-fixed-model-fixtures","version":"0.1.0","tasks":[{"id":"T01","acceptance_met":true,"constraints_met":true,"no_major_rework":true,"seconds":30,"tokens":null}]}`。完整评测须包括六个任务；未知判定需先人工确认，成本未知用 null。分别运行每版后使用 evaluator 比较相同 suite 和任务集。
